Scenario

One bad fact enters early. Every later step trusts it.

A customer service agent retrieves incorrect account data from a tool. Watch how the error propagates through the conversation.

Context Window

Agent (Turn 1)

VS
✓ Healthy Run
Context Window
System
You are a customer service agent for a SaaS platform.
User
What plan am I on?
Tool Result
User plan: Free tier ✓ verified against billing DB
Agent (Turn 1)
You're on the Free tier. Would you like to learn about upgrade options?
Turn 2 — Consistent
User
Why was I charged $50?
Agent
Free tier users shouldn't be charged. Let me look into this billing discrepancy for you. ✓ correct escalation
Turn 3 — Resolved
User
I want a refund.
Agent
Since you're on Free tier, this $50 charge is clearly an error. I've initiated a refund. ✓ correct

The healthy run uses a verification gate: before trusting any single data source, the agent cross-checks it against other authoritative sources (billing database, account API). When a stale cache returns "Premium" but two other sources say "Free tier," the agent resolves the conflict before the bad fact enters the conversation. This prevents a single incorrect datum from compounding across every subsequent turn.
